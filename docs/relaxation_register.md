# 放寬與補償清單

第一版：2026-10-14（Phase 7 結案期間）。使用者 2026-10-14 決定從本專案開始建（ADR-0020 決定 3，`docs/decisions/0020-flow-shift-left.md` 第 18 行）。背景是流程回顧的 E1「放寬與補償登記表」與共同模式 4「放寬的依據只在一個設計上量過」（`docs/notes/flow_retro/README.md` 第 26、49 行）：IR 只在 nom_tt 檢查、resizer 用固定 margin 代替 ss −40°C、golden 誤差，三項的依據都只在 PicoRV32 版 soc_top 量過，換成 Hazard3 時全部失效。

## 這份表是什麼、怎麼用

**收錄範圍**：任何讓 signoff 或驗證比「理想做法」寬鬆，或用估計、margin、假設代替量測的決定。例如加長週期、只給 resizer 部分 corner、用固定 margin 代替某個 corner、hold／setup margin、slew 上限的例外、golden 誤差、借用另一個設計的誤差、SRAM .lib 的 margin 與下限、placeholder .lib、IR 的檢查方式與供電假設、clock jitter／duty cycle 的假設、EQY 與 LVS 的範圍、precheck 的判斷方式、DRC 的例外與容許值，以及列為已知限制而沒有修、或決定延後處理的項目。已經拿掉或被取代的也列出來，標明狀態，讓「依據只在一個設計上成立」的歷史看得到。

**沒有收錄的**：純工具或流程本身的限制，跟 signoff PASS 條件的寬嚴無關的，例如 `make py-check` 的範圍、pin 規劃 hook 看不到 Bash 修改、DV testbench 的計數設定。這些在各 Phase exit review 的「已知限制」。

**怎麼用**：
1. **新增**：做出新的放寬或補償時，同一個 commit 在表裡加一列，八個欄位都要填。依據沒有量過就在「在哪個設計量的」寫「沒有量測（假設）」。
2. **每個 Phase 收尾**（skill `phase-exit-review`）：逐列檢查兩件事。第一，「依據的設計」是不是現在的設計；第二，「原因」是不是還在。依據不是現在設計的，要在現在設計上重新量測，或寫明為什麼不用量。原因已經不在的，要評估能不能拿掉這項放寬。
3. **換設計、換 macro、換平台、換工具版本，或某個原因被修掉時**：逐列看「什麼情況要重新驗證」，符合的列做 what-if（只重跑 STA、單獨重跑某個 step 或植入錯誤），結果寫進該列。
4. **狀態**只有三種：**有效**；**已回收**（放寬已經拿掉）；**已被取代**（寫明被哪個決定取代）。

**欄位與編號**：編號的字母只是方便分組，表格是同一張。T 時序與 resizer、I IR、S SRAM macro 的 .lib 與 characterization、D DRC／LVS／precheck、V 功能與 formal 驗證、G golden 與可重現性、O 其他。

**出處的寫法**：檔名＋行號、ADR 決定編號或 commit。`docs/phase_exit/phase7.md` 在本表第一版時還是沒提交的草稿，`0d47a3d`（2026-10-15）提交；表中引用它的行號，2026-10-16 依當天的 phase7.md 核對過（ADR-0022 決定 13）。「carryover」指 `runs/p7_exit_draft/carryover.md`，引用的是它的列編號（例如 6-1、N7）；`runs/` 不進版控，這份檔案收錄在 `docs/evidence/arvinsa-rtl-gds/runs/p7_exit_draft/carryover.md`（ADR-0021 決定 7）。
